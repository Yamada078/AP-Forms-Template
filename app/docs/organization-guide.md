# เริ่มใช้ AP+forms ภายในองค์กร

รุ่นนี้มีบัญชีสมาชิกภายใน AP+forms ผู้ดูแลจัดการสมาชิกและกำหนดผู้ตอบผ่านหน้าจอได้ หนึ่งระบบที่ติดตั้งใช้สำหรับหนึ่งองค์กร

## ตั้งค่าครั้งแรก

หลังติดตั้งและตั้ง `TEAM_KEY` แล้ว เปิด `/account.html` ตั้งชื่อองค์กร URL โลโก้ถ้ามี ชื่อผู้ดูแล ชื่อบัญชี และรหัสผ่าน ใส่ `TEAM_KEY` ในช่องรหัสตั้งค่าระบบเพื่อยืนยันสิทธิ์สร้างองค์กร

ชื่อบัญชีใช้ตัวอักษรอังกฤษ ตัวเลข และ `. _ @ + -` ได้ จะใช้ชื่ออีเมลเป็นชื่อบัญชีก็ได้ แต่ระบบไม่ได้ตรวจยืนยันอีเมล รหัสผ่านยาวอย่างน้อย 12 ตัวอักษรและไม่เกิน 72 ไบต์ ตัวอักษรไทยใช้หลายไบต์ต่อหนึ่งตัว

ตั้งค่าได้ครั้งเดียว หลังตั้งแล้ว `TEAM_KEY` ไม่สามารถใช้เข้าสู่ Builder หรือข้ามสิทธิ์บัญชีได้ เก็บ Secret นี้ไว้เพราะระบบยังใช้ลงนามการทำงานร่วมกัน

## ภาษาในหน้าจอ

ใช้ **Language / ภาษา** เลือกไทยหรืออังกฤษ หน้าจอเปลี่ยนภาษาโดยคงข้อมูลที่กำลังกรอกไว้ ส่วนชื่อองค์กร ชื่อฟอร์ม คำถาม และคำตอบยังคงข้อความเดิม ดู [รายละเอียดภาษา](languages.md)

## เชิญสมาชิก

1. เปิด **บัญชีองค์กร** จาก Builder
2. กรอกชื่อสมาชิก ชื่อบัญชี และเลือกสิทธิ์
3. กด **สร้างบัญชีและลิงก์เชิญ**
4. ส่งลิงก์และชื่อบัญชีให้สมาชิกผ่านช่องทางที่องค์กรใช้
5. สมาชิกเปิดลิงก์ ตั้งรหัสผ่าน แล้วเข้าสู่ระบบ

ระบบยังไม่ส่งอีเมลอัตโนมัติ ลิงก์ใช้ได้ครั้งเดียวภายใน 24 ชั่วโมง กด **ออกลิงก์ใหม่** หากลิงก์หมดอายุหรือสมาชิกลืมรหัสผ่าน ลิงก์ใหม่ยกเลิกลิงก์เก่าของบัญชีนั้น

| สิทธิ์ | ทำอะไรได้ |
| --- | --- |
| ผู้ดูแล | จัดการองค์กร สมาชิก การเชื่อมต่อแอป ฟอร์ม คำตอบ และคลังคำถาม |
| ผู้สร้างฟอร์ม | จัดการฟอร์ม คำตอบ คลังคำถาม ชุดคำถาม และสิทธิ์ผู้ตอบร่วมกัน |
| ผู้ตอบ | ดูและตอบฟอร์มที่ตนได้รับอนุญาต |

ผู้สร้างฟอร์มในองค์กรเดียวกันเข้าถึงงานร่วมกัน รุ่นนี้ยังไม่มีการแยกฟอร์มตามแผนกหรือเจ้าของ และไม่มีระบบหลายองค์กรในฐานข้อมูลเดียว

การเปลี่ยนสิทธิ์หรือปิดบัญชียกเลิกเซสชันเดิม สมาชิกต้องเข้าสู่ระบบใหม่หลังเปลี่ยนสิทธิ์ ระบบป้องกันการปิดหรือลดสิทธิ์ผู้ดูแลที่ใช้งานได้คนสุดท้าย บัญชีที่ยังรอคำเชิญต้องรับคำเชิญก่อนแก้สิทธิ์ผ่านหน้าจอ

## จำกัดผู้ตอบ

เปิดฟอร์ม → **Publish Settings** → **กำหนดสิทธิ์ผู้ตอบ** แล้วเลือก:

| การเข้าถึง | ใครตอบได้ |
| --- | --- |
| ทุกคนที่มีลิงก์ | เปิดและตอบได้โดยไม่ต้องเข้าสู่ระบบ |
| สมาชิกองค์กร | บัญชีสมาชิกที่เปิดใช้งานและเข้าสู่ระบบแล้ว |
| เฉพาะสมาชิกที่เลือก | สมาชิกที่เลือกไว้และเข้าสู่ระบบแล้ว |

ฟอร์มใหม่หลังตั้งองค์กรเริ่มเป็น **สมาชิกองค์กร** การเปลี่ยนสิทธิ์มีผลทันทีโดยไม่ต้อง Publish ใหม่ รวมถึงลิงก์ที่ส่งไปแล้ว สมาชิกที่เข้า `/account.html` จะเห็นรายการฟอร์มที่เปิดรับคำตอบและตนมีสิทธิ์ตอบ

ผู้ดูแลไม่ได้มีสิทธิ์ตอบฟอร์มแบบเลือกสมาชิกโดยอัตโนมัติ หากต้องการตอบ ให้เลือกบัญชีผู้ดูแลด้วย Preview ใน Builder ใช้ทดลองรูปแบบฟอร์มได้

คำตอบจากสมาชิกเก็บ `respondent_user_id` และข้อมูลบัญชีที่ระบบยืนยันไว้ใน `respondent_meta._account` ชื่อที่ผู้ตอบกรอกเองเป็นอีกข้อมูลหนึ่ง ผู้ตอบเปลี่ยนข้อมูลยืนยันบัญชีนี้ผ่าน payload ไม่ได้

## เชื่อมเว็บที่มีสมาชิกอยู่แล้ว

การลงทะเบียน **Application** ใช้ระบุแอปและสิทธิ์ API ส่วนบัญชีสมาชิกใช้ระบุคนที่เข้าสู่ระบบ ทั้งสองอย่างมีหน้าที่ต่างกัน

- ถ้าผู้ตอบใช้บัญชี AP+forms: เชิญสมาชิก แล้วส่งไปยังลิงก์ฟอร์มที่จำกัดสมาชิก
- ถ้าเว็บภายนอกสร้างหน้าตอบของตนเอง: ใช้เซิร์ฟเวอร์ของเว็บเรียก API ตาม [ตัวอย่างเชื่อมแอป](app-integration-walkthrough.md) กับฟอร์มที่ตั้งเป็นทุกคนที่มีลิงก์
- ถ้าต้องการใช้บัญชีองค์กรเดิมเข้าสู่ AP+forms: รุ่นนี้ยังไม่มี SSO/OIDC และยังไม่ยืนยันบัญชีภายนอกจาก metadata ที่ส่งผ่าน API

API ปฏิเสธการอ่านและส่งคำตอบฟอร์มแบบสมาชิกหรือแบบเลือกสมาชิกด้วยรหัส Application เพื่อป้องกันการใช้รหัสแอปข้ามการเข้าสู่ระบบ การเชื่อมตัวตนจากระบบอื่นเป็นงานขั้นถัดไป

## การดูแลบัญชี

เซสชันหมดอายุใน 8 ชั่วโมง เก็บในคุกกี้ HttpOnly การออกจากระบบยกเลิกเซสชันนั้น การเปลี่ยนรหัสผ่านยกเลิกทุกเซสชันและลิงก์ตั้งรหัสผ่านเก่าของบัญชี การพยายามเข้าสู่ระบบซ้ำมีการจำกัดความถี่

หากผู้ดูแลทุกคนลืมรหัสผ่าน ต้องให้ผู้ดูแลฐานข้อมูลช่วยกู้บัญชี รุ่นนี้ยังไม่มีอีเมลกู้บัญชีหรือหน้ากู้ระบบด้วย `TEAM_KEY`

รุ่นนี้เป็นรุ่นทดลองสำหรับติดตั้งและพัฒนาต่อ ยังไม่มี SSO, MFA หรือบันทึกกิจกรรมการจัดการสมาชิก ก่อนใช้กับงานสำคัญควรทดสอบสิทธิ์จริงขององค์กรและจัดแผนสำรองฐานข้อมูล
